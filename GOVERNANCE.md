# Governance

## Ownership

Each project, shared knowledge entry, skill, agent, and integration should identify a responsible team or maintainer. Ownership means reviewing changes, confirming technical accuracy, and periodically checking that the material remains useful.

## Maturity

Contributions may use these maturity labels in their manifests:

- `draft`: useful working material that may be incomplete.
- `reviewed`: checked by a domain or project maintainer.
- `stable`: depended on by multiple users or projects.
- `deprecated`: retained temporarily with a documented replacement.

## Promotion

Project material should be promoted into a shared area when it is used by multiple projects or has become a stable institutional practice. Promotion should preserve attribution and leave a link from the original project location.

## Changes and review

- Project maintainers approve project-local content.
- Domain owners review shared scientific knowledge.
- Skill owners review behavioral and tooling changes.
- Security-sensitive integrations require an appropriate platform owner.
- Breaking changes should include migration notes and updates to affected evaluations.

## Information handling

This repository must not contain passwords, API keys, access tokens, export-controlled information, sensitive personal data, or data whose license prohibits redistribution. Document how to obtain protected resources instead of storing them here.
